# v0.4 — Per-shell and per-project switching

**Goal:** let different terminals use different accounts at the same time, and let a repo pick its own account automatically.
**Requirement:** F11. **Prereq:** v0.3 accepted; SPIKE-0 answers on `CLAUDE_CONFIG_DIR` / `CODEX_HOME` Keychain behavior.

## Tasks

### A. CLI (`swaplane`)
- [ ] Flesh out `swaplane-cli` with swift-argument-parser, talking to the app over the IPC socket (auto-launch headless app if needed). Peer validation + command allowlist per SECURITY.md.
- [ ] Commands:
  - `swaplane list [--json]`
  - `swaplane current [--tool claude-code] [--shell]`
  - `swaplane use <profile> [--global]` (default: current shell only → prints exports for `eval`; `--global` performs the v0.1 global switch)
  - `swaplane env [--shell zsh|bash|fish]` → emits validated, shell-quoted exports
  - `swaplane shell-hook <zsh|bash|fish>` → prints the hook snippet
  - `swaplane project init|show|trust|untrust`
  - `swaplane doctor` → secret-free diagnostics
- [ ] Optional installer: symlink into `/usr/local/bin` or `~/.local/bin` with explicit user approval; uninstall path.
- [ ] Stable exit codes and `--json` output for scripting.

### B. Per-shell mode
- [ ] Materialize per-profile config dirs under `~/Library/Application Support/Swaplane/shells/<profileUUID>/` (0700), populated from the Vault on demand and kept in sync (capture-back on shell exit / periodic / on `swaplane sync`).
- [ ] Claude Code: set `CLAUDE_CONFIG_DIR`; write credentials where the CLI will look (Keychain service name per SPIKE-0, or file fallback with 0600).
- [ ] Codex: set `CODEX_HOME` with 0600 `auth.json`; document plaintext-file caveat; prefer keyring mode if supported.
- [ ] Prompt integration: `SWAPLANE_PROFILE` / `SWAPLANE_LABEL` env for PS1/starship; menu bar shows count of shells with overrides; Activity log notes shell switches.
- [ ] Token-refresh safety: when the CLI in a shell refreshes tokens, ensure the Vault copy updates (capture-back) so other shells/global don't use a stale refresh token. Add tests/simulation.

### C. Per-project rules
- [ ] `.swaplane` TOML file: 
  ```toml
  [profiles]
  claude-code = "Work"      # label or UUID
  codex-cli   = "Personal"
  ```
- [ ] Discovery: walk up from `$PWD` to `$HOME`; nearest wins; global rules fallback in `state.json` (path-prefix → profile).
- [ ] **Trust model**: first time a rule file at a new path/hash is seen, require `swaplane project trust` or GUI approval; changed file hash re-prompts. Rules can reference only existing profiles; unknown labels produce a warning, not an error that blocks the shell.
- [ ] Shell hook (`chpwd`/`precmd`) calls `swaplane env --shell`; must be fast (< 30 ms warm; cache; no-op if unchanged) and fail silent-safe (never break the user's prompt).
- [ ] GUI: Projects sidebar section listing rules, trust state, and which shells currently use them.

### D. Tests and docs
- [ ] Shell hook tests (zsh/bash/fish) in a pty harness: quoting, injection attempts (`$(…)`, newlines, quotes in labels), allowlisted keys only.
- [ ] Rule discovery + trust tests; malicious `.swaplane` fixtures.
- [ ] IPC auth tests (wrong UID/peer rejected).
- [ ] Docs: `docs/CLI.md` (command reference, hook install instructions), update SECURITY.md/ARCHITECTURE.md.

## Acceptance criteria

1. Two terminals simultaneously run `claude`/`codex` as two different profiles with no cross-talk; global active profile unchanged.
2. `cd` into a repo with a trusted `.swaplane` switches that shell's account automatically; leaving the repo reverts to the global/default.
3. Untrusted/modified rule files never apply silently.
4. Hook adds < 30 ms to prompt in the warm path and never prints errors to the user's prompt on failure.
5. After using a profile in two shells and globally, no profile ends up with an invalidated/stale token because of refresh races (simulation test + manual check).
6. Env output cannot be abused for injection (fuzz tests pass); only allowlisted variables emitted.
7. All tests, security checklist, accessibility checks pass.

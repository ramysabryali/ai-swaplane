# v0.2 — Live usage and Touch ID gate

**Goal:** show live usage for each profile in the menu bar and popover, and require biometric/password auth for sensitive actions.
**Requirements:** F8 F9. **Prereq:** v0.1 accepted; SPIKE-0 usage findings for Claude.

## Tasks

### A. Usage
- [ ] `UsageProvider` protocol and `UsageSnapshot { windows: [UsageWindow{label, usedFraction, resetsAt}], planName?, fetchedAt, status }`.
- [ ] `ClaudeCodeUsageProvider` per ADAPTERS.md (undocumented endpoint, feature-flagged `liveUsage`). Pure parsing function with fixture tests; tolerant to missing/extra fields.
- [ ] `HTTPClient` wrapper with host allowlist, timeouts, no redirects to other hosts, user agent `Swaplane/<version>`; reads credential from Vault per call; never logs headers/bodies.
- [ ] `UsageService` actor: polling cadence (active 60 s, others 5 min), jitter, exponential backoff on errors/429, pause on sleep/lock/low-power, manual refresh, cached last-good value with staleness indicator.
- [ ] Token expiry handling: 401 → profile "needs sign-in" badge; **do not refresh tokens ourselves**.
- [ ] Link Claude Desktop profile ↔ Claude Code profile (same identity) so Desktop rows can show linked usage.
- [ ] Settings: menu bar display mode (icon · icon + % · compact bar · ring), which window drives the menu bar value (5-hour / weekly / highest), warning thresholds (70/90 %), reset notifications (optional, `UserNotifications`).
- [ ] Popover rows: usage mini-bars + "resets in 1h 12m".
- [ ] Suggestion banner: when active profile ≥ 90 % and another has headroom → "Switch to <label>?" (suggestion only; no auto switch).
- [ ] Graceful degrade: "Usage unavailable" with reason; switching unaffected.

### B. Touch ID gate
- [ ] `AuthGate` actor with `LocalAuthentication` (`.deviceOwnerAuthentication`), reuse window modes: Off · Every action · 1 / 5 / 15 min · Until lock.
- [ ] Gated actions: switch, remove profile, reveal diagnostics, change security settings, (v0.5: export/backup).
- [ ] Optionally create credential Keychain items with `SecAccessControl(.userPresence)`; migration path for v0.1 items (re-save under new ACL with progress UI).
- [ ] Settings → Security UI, clear explanation of each mode; cancelled auth leaves state unchanged.
- [ ] CLI/IPC: gated commands return a structured `authRequired` result that triggers the GUI prompt.

### C. Tests and docs
- [ ] Usage parsing fixtures (normal, partial, error shapes), scheduler tests with fake clock, backoff tests.
- [ ] Host allowlist CI check includes the usage host(s).
- [ ] `AuthGate` tests with a fake `LAContext` protocol.
- [ ] Update SECURITY.md, ADAPTERS.md Verified usage fields, UX.md.

## Acceptance criteria

1. Menu bar shows accurate usage for the active Claude profile within one polling interval of a real change; matches the vendor UI within rounding.
2. With the network off or the endpoint failing, the app shows "unavailable/stale" and switching still works.
3. Polling stops when the Mac sleeps/locks and resumes after.
4. No credential appears in logs, errors, or network-diagnostic output; only allowlisted hosts contacted (verify with `nettop`/Little Snitch).
5. Gate: each mode behaves as documented; cancel = no action performed; reuse window honored and expires.
6. Existing v0.1 profiles migrate without data loss.
7. Menu bar usage display renders correctly on all attached displays and in Light/Dark.
8. All tests, security checklist, accessibility pass complete.

## Out of scope

Codex/ChatGPT usage (v0.3), usage history charts, automatic failover.
